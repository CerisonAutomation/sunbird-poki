## Submission steps (platform-side)

### Step 1 — Poki for Developers account

<https://app.poki.dev/signin>

### Step 2 — Upload the build and thumbnails

1. `pnpm upload:poki` — builds the game and proves the upload shape (`pnpm verify:upload`).
2. Open <https://inspector.poki.dev/> and **drag the folder `poki-upload/`** onto the drop zone (the Inspector takes a folder, and `index.html` — everything inlined — sits at its root).
   - Not the repository folder, not a GitHub "Download ZIP" (that wraps everything in `sunbird-main/`), not a `.zip`: those are the four ways to get its "missing index.html" error. Details and fixes: [`docs/poki/UPLOAD.md`](./docs/poki/UPLOAD.md).
3. Inspector auto-tests the build; walk the Event Log, External Resources, Image Optimization, Scaling and mobile (QR) modules.
4. In Poki for Developers: upload `sunbird-thumbnail-1024.png` (and the 628 px derivative if the form asks for the exact minimum).
5. Record and upload the **animated thumbnail** (3–5 s of gameplay) — see Step 5.

### Step 2b — Privacy Policy URL, then the custom CSP

Poki stores **no** custom CSP until the game has a privacy policy URL, and the policy has to be
reachable both as a live public page and from inside the game. Both halves ship; the dashboard
half is manual:

1. **Game settings → Privacy Policy URL** — paste `https://sunbird-snowy.vercel.app/privacy`.
   - The page is generated, not hand-written: `pnpm gen-legal` writes `public/privacy.html` from
     `src/game/legal*.ts`, and `vercel.json` rewrites `/privacy` to it. Regenerate and redeploy
     before changing anything a player reads.
   - In-game: Settings → Privacy Policy renders the same document, and on Poki the "open the
     hosted page" button goes through `PokiSDK.openExternalLink` (never `window.open`, never
     `target=_blank` — `scripts/audit-zips.mjs` fails the artifact if either appears).
2. **Settings → Content Security Policy** — run `pnpm verify:csp` first (it proves the document
   matches the bytes you just uploaded), then paste the host list and the one-line reason for each
   from [`docs/poki/CSP_REQUEST.md`](./docs/poki/CSP_REQUEST.md). It is generated from the same
   `EXTERNAL_HOSTS` array (`scripts/gen-csp-request.ts`), so it cannot drift from the policy:
   five hosts for the Poki build — `game-cdn.poki.com`, `netlib.poki.io`, `auds.poki.io`,
   `stun.l.google.com`, `turn.rtc.poki.com`.
3. **Re-upload the build after the CSP is reviewed**, so the CDN cache resets and the Inspector
   tests the artifact that will actually ship under the new policy.

### Step 2c — Confirm the game id against the dashboard

Rule `TOOL-09`, and the only part of the SDK wiring a machine cannot check:

1. On the Poki developer dashboard, open the game and copy its id.
2. Diff it against `VITE_POKI_GAME_ID` and `VITE_POKI_NETLIB_GAME_ID` in `package.json`'s
   `build:poki`. All three must be the same value — AUDS and Netlib are the same game, and a
   test fails the build if they ever diverge.
3. If it changed: edit `build:poki` (the only place the id lives), `pnpm build:poki`, then
   confirm the new id is in `dist-poki/index.html`, in neither other edition
   (`pnpm isolation:check`), and that `pnpm verify:csp` still passes.

### Step 3 — Inspector QA review

- Expect **zero** external-resource and image-weight warnings (there are no raster assets in the game itself).
- Confirm the event log shows the documented sequences (loading → gameplay start/stop → break → resume).

### Step 4 — Playtest, then final submission

1. **Poki Playtest** (rule `EA-09`) — upload the build to Playtest and record real first-run
   sessions. The client already emits every funnel stage (`src/game/Funnel.ts`), so the recordings
   are for what the events cannot show: where a player hesitates, what they tap first, whether the
   gated shop auto-open reads as help or as an interruption. Aggregating those stages server-side
   is parked work, not a submission blocker
   ([`docs/archive/GAME_BACKLOG_2026-09-23.md`](./docs/archive/GAME_BACKLOG_2026-09-23.md) §4).
2. Player-fit test → web-fit test → final review.

### Step 5 — Post-launch (optional)

- [ ] Animated thumbnail (hover video) for global release
- [ ] "Sign in with Poki" button on the profile screen (passive `getUser()` ships today; `login()` is deliberately not called at boot because it reloads the page)
- [ ] AUDS cross-device save once the dashboard id is confirmed (Step 2c)
- [ ] Netlib/server-approved multiplayer for the portal artifact

## Critical commitments at submission

1. **Web exclusivity** — `sunbird-poki.zip` is exclusive to Poki. The generic artifact (`sunbird-generic.zip`) is the non-exclusive build for itch.io / GameDistribution / etc.; keeping them separate artifacts is what makes the pledge honest.
2. **Animated thumbnail** — required for global release, not for initial approval.
3. **Multiplayer is single-player-first on the portal artifact** — the Rust room server stays out of the Poki zip.
